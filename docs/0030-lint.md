# 0030: vp_lint_diagram

## Context

Reviewing a diagram by hand (unconnected actors, shapes past the
boundary, touching use cases, missing docs) was the first thing every
modelling session did, and the agent did it inconsistently.

## Decision

- `vp_lint_diagram {vpp_url?, include_info?}`: read-only; defaults to the
  active diagram. Findings are `{rule, severity, message, suggestion,
  elements[{view_id, model_id, name}]}` plus a per-severity summary.
- Rules: unconnected_actor, unconnected_use_case, actor_inside_boundary,
  outside_container, empty_container, overlap, crowded (< 6px),
  duplicate_name (different models only), duplicate_number and
  numbering_gap (3+ numbered names), self_relationship,
  include_extend_ends (error), actor_to_actor_association,
  missing_documentation.
- `lint.DiagramLinter` runs on the extractor's JSON, never on VP, so every
  rule is unit-tested on built graphs (mutation-checked: inverting
  containment fails `childPastContainerEdgeIsFlaggedChildInsideIsNot`).
- Findings are advice. The agent turns them into a previewed batch; the
  user approves.

## Consequences

- New rules are plain JSON logic plus a test; no VP probe needed.
- Include/extend *direction* is not linted: it is not inferable from the
  graph alone.
